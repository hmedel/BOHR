# CLAUDE.md - BOHR RAG v2

## Overview

BOHR RAG v2 is an educational RAG (Retrieval-Augmented Generation) chatbot for "Estructura de la Materia" (Atomic/Molecular Structure) at FESC-UNAM. Multi-user system with JWT authentication, persistent conversations, formative exams with adaptive difficulty, sentiment analytics, streaming responses, and LaTeX-rendered mathematical responses.

**Public URLs:**
- Frontend: https://chat.bohrbot.space
- API: https://api.bohrbot.space

**Python environment:** `/home/medel/.julia/conda/3/x86_64/envs/bohrenv/bin/python`

## Architecture

```
Frontend (index.html)              →  FastAPI Backend (port 8000)
Marked.js + KaTeX + hljs              ├── RAG Engine (LangChain + ChromaDB + Ollama embeddings)
Static HTTP server (port 9000)         ├── Exam Engine (5 questions, adaptive Bloom difficulty)
                                       ├── Analytics Engine (TextBlob sentiment, topic detection)
                                       ├── Qualitative Evaluator (Bloom/SOLO)
                                       ├── Auth (JWT + SHA256)
                                       └── SQLite (users, conversations, exams)

External services:
- Ollama (localhost:11434) → nomic-embed-text for embeddings
- DeepSeek API → deepseek-chat for LLM responses
- Cloudflare Tunnel → public HTTPS access
```

## Query Flow State Machine (main.py /query and /query/stream)

```
User message arrives
    │
    ├─ matches exam patterns? ──→ Offer exam or "not ready"
    ├─ "cancelar examen"? ──────→ Cancel active exam
    ├─ "sí, comenzar"? ────────→ Build difficulty_profile from past exams
    │                              → Create exam, generate Q1
    ├─ has active exam? ────────→ Evaluate answer → next Q or final summary
    │                              → Mark exam status='completed' when done
    └─ else ────────────────────→ Normal RAG flow:
         1. Sentiment analysis (TextBlob)
         2. Topic detection (word-boundary keywords, 7 topics)
         3. Complexity assessment
         4. Bloom level classification → saved to message.bloom_level
         5. Save user message
         6. Build conversation_history (last 6 messages) for context
         7. Multi-source vector search (3 sources × 10 chunks)
         8. Build synthesis prompt (includes conversation history)
         9. Call DeepSeek (stream=True → SSE tokens; stream=False → full text)
        10. Unicode math post-processing
        11. Save response + update student_progress
```

## RAG Pipeline Details

```
query_multi_source_with_synthesis(query, sources_count=3, chunks_per_source=10,
                                   conversation_history=None, stream=False):
    1. Build history_block from last 6 messages (assistant responses truncated to 400 chars)
    2. Embed query via Ollama (nomic-embed-text)
    3. Search EACH of 7 documents separately (10 chunks per doc)
    4. Score sources by relevance (chunks × position weights)
    5. Select top 3 sources (30 chunks total, ~9,000 tokens)
    6. Build synthesis prompt with history + strict LaTeX rules
    7. If stream=True → return prompt for caller to stream
       If stream=False → call DeepSeek (max_tokens=4000, temperature=0.5)
    8. Post-process: fix $→$$ for multiline, remove Unicode math duplicates
    9. Return synthesized answer + sources + response time
```

## Exam System (adaptive difficulty)

- **Trigger**: Pattern matching ("examen", "evalúame", "prueba", etc.)
- **Prerequisites**: ≥3 queries + ≥2 different topics
- **Adaptive difficulty**: `get_difficulty_profile()` checks past ExamResult records
  - ≥80% correct → start at `aplicar`, max `crear`
  - 60–79% correct → start at `comprender`, max `evaluar`
  - <60% correct → start at `recordar`, max `aplicar`
  - No history → start at `comprender`, max `analizar` (default)
- **Format**: 5 questions, one at a time, mostly multiple choice
- **Feedback**: Immediate after each answer (without revealing correct answer)
- **Final summary**: Performance level, real Bloom/SOLO distributions, strengths, action plan
- **State**: Stored in `exams.exam_data` JSON (includes `difficulty_profile`)
- **Status**: `active` while in progress → `completed` when all responses saved

## Analytics & Progress

- **`/me/progress`**: Per-user endpoint returning total queries, topics (sorted by freq),
  Bloom distribution, complexity distribution, exams completed, trend label
- **Progress panel**: Sidebar widget in frontend, refreshes on login and after each query
- **`analyze_participation.py`**: Standalone script generating HTML report + CSV snapshots
  in `analytics/reports/` and `analytics/snapshots/`
- **`/analytics`**: Admin-only endpoint serving the HTML report in real time (token via query param)

## Welcome Modal (onboarding)

- Shown on first login when `total_queries === 0` AND no `bohr_welcomed_{id}` key in localStorage
- Explains: how to ask questions, LaTeX rendering, exams, progress panel
- Dismissed by clicking either button → sets localStorage flag (never shows again on that device)

## Topic Detection (analytics_engine.py)

7 topics with word-boundary matching (no single-letter keywords):
- `estructura_atomica`: átomo, electrón, protón, neutrón, número atómico, …
- `mecanica_cuantica`: cuántico, función de onda, heisenberg, hamiltoniano, …
- `enlaces_quimicos`: enlace, iónico, covalente, electronegatividad, …
- `espectroscopia`: espectro, fotón, emisión, rydberg, balmer, …
- `orbitales`: orbital, orbital s/p/d/f, hibridación, número cuántico, aufbau, …
- `termodinamica`: entalpía, entropía, gibbs, …
- `estructura_molecular`: geometría molecular, vsepr, momento dipolar, …

## Frontend Streaming

`sendMessage()` calls `/query/stream` and consumes SSE:
- `{"type":"token","content":"..."}` → appended to live bubble with blinking cursor `▍`
- `{"type":"meta",...}` → renders final content, adds sources/time/feedback footer
- `{"type":"error",...}` → shows error in bubble
- Exam/state flows are wrapped in SSE by the backend transparently

## Database Schema (SQLite)

8 tables:
- **users**: id, username, email, hashed_password, full_name, is_admin, created_at
- **conversations**: id, user_id, title, created_at, updated_at
- **messages**: id, conversation_id, role, content, sources, sentiment_score/label, query_complexity, topics, bloom_level, solo_level, feedback, response_time
- **query_logs**: id, user_id, query, sources_found, top_k_used, response_time, created_at
- **student_progress**: id, user_id, total_queries, topics_explored, complexity_distribution, first/last_query_date
- **exams**: id, user_id, title, exam_data (JSON incl. difficulty_profile), topics_covered, total_questions, status
- **exam_responses**: id, exam_id, user_id, question_number, student_answer, bloom_level, solo_level, evaluation_data, sentiment_score/label
- **exam_results**: id, exam_id, user_id, predominant_solo_level, strengths, improvement_plan, bloom_distribution, solo_distribution

## Common Issues

- **Backend won't start with `conda activate`**: Use full path to Python — `conda activate` fails in non-interactive shells
- **Equations truncated**: LLM_MAX_TOKENS too low (now 4000)
- **LaTeX broken in chat**: Marked.js corrupting `$` before KaTeX — fixed by placeholder system in renderContentWithLatex()
- **Unicode math in responses**: DeepSeek duplicates equations as Unicode — fixed by _remove_unicode_math_duplicates()
- **Slow queries (~35–50s)**: Normal — searches 7 docs × 10 chunks + LLM synthesis. Streaming makes wait feel shorter.
- **401 Unauthorized**: JWT expired (7-day TTL) or invalid username
- **Exam stuck as `active`**: Run `UPDATE exams SET status='completed' WHERE id IN (SELECT e.id FROM exams e WHERE (SELECT COUNT(*) FROM exam_responses er WHERE er.exam_id=e.id) >= e.total_questions);`
- **Topics all showing `orbitales`**: Was caused by single-letter keywords (`s`, `p`, `d`, `f`) — fixed in analytics_engine.py with word-boundary matching
- **Bloom level empty in messages**: Fixed — qualitative_evaluator.classify_bloom_level() now called on every RAG query
- **ChromaDB deprecation warning**: Harmless. Upgrade: `pip install langchain-chroma` and update import in rag_engine.py
